# Apple-1 Pico Cassette Interface Guide

Technical reference, hardware wiring, and operating manual for the physical audio cassette and SD-card interface in **apple1_pico** (`aci.c`).

---

## 1. Hardware Wiring & Pinout

The emulator uses two GPIO pins on the Raspberry Pi Pico / Pico 2 to communicate directly with a standard compact cassette recorder:

| Function | Pico Pin | Direction | Target Cassette Jack | Signal Characteristics |
| :--- | :--- | :--- | :--- | :--- |
| **Tape Out (`W`)** | `GP0` (Pin 1) | Output | **MIC** or **Line-In** | 3.3 V square wave (1000 Hz / 2000 Hz) |
| **Tape In (`R`)** | `GP26 / ADC0` (Pin 31) | Input | **EAR** or **Headphone** | 1.65 V DC-biased AC audio (0 V – 3.3 V) |
| **Ground** | `GND` (Pin 3 / Pin 38) | Common | **Sleeve / Ground** | Common audio ground reference |

### Wiring Schematic

```text
  WRITING TO TAPE (Pico -> Cassette Recorder MIC / Line-In)
  ---------------------------------------------------------
                     1uF - 10uF
  GP0 (Pin 1) o---------||---------+---------> To Cassette MIC / Line-In
                                   |
                                  [ ] 10k Potentiometer (Voltage Divider)
                                  [ ] <--- Wiper to MIC (set ~20-50mV for MIC)
                                   |
  Pico GND    o--------------------+---------> To Cassette Sleeve / Ground


  READING FROM TAPE (Cassette Recorder EAR / Headphone -> Pico)
  -------------------------------------------------------------
  Pico 3.3V   o--------[ 10k ]-----+
                                   |
                     1uF - 10uF    +---------> GP26 / ADC0 (Pin 31)
  Cassette    o---------||---------+
  EAR / Phones                     |
                                [ 10k ]
                                   |
  Pico GND    o--------------------+---------> To Cassette Sleeve / Ground
```

> **Hardware Tip:** Cassette `MIC` inputs are very sensitive (~10 mV–50 mV). Use the 10 kΩ potentiometer to attenuate the 3.3 V output from `GP0` so the tape does not saturate or clip. On playback, set the cassette player volume to roughly **50%–75%**—the firmware automatically calibrates the 1.65 V DC midpoint before reading.

## 2. User Operating Guide

From the Woz Monitor (`\` prompt), type **`C100R`** and press `RETURN` to enter the Apple Cassette Interface (`*` prompt).

### Command Reference

| Command Example | Mode | Description |
| :--- | :--- | :--- |
| `*0300.03FFW` | **Physical Cassette** | Writes `$0300`–`$03FF` as 1000/2000 Hz FSK audio out of `GP0` |
| `*0300.03FFR` | **Physical Cassette** | Listens on `GP26 (ADC0)` and loads FSK audio into `$0300`–`$03FF` |
| `*0100.01FFW 0300.03FFW` | **Physical Cassette** | Streams multiple memory ranges back-to-back in one recording |
| `*0300.03FFW PROG.DAT` | **SD Card** | Saves range(s) to `/apple1/tape/PROG.DAT` and creates `PROG.MAP` |
| `*0300.03FFR PROG.DAT` | **SD Card** | Loads `/apple1/tape/PROG.DAT` into `$0300`–`$03FF` |
| `*R` or `*R PROG.DAT` | **SD Card** | Loads `TAPE.DAT` (or `PROG.DAT`) using ranges from its `.MAP` file |
| `*L` or `*DIR` | **SD Card** | Lists saved tape files on the SD card that have a `.MAP` file |
| `*?` | **Help** | Displays the on-screen command summary |
| `*` *(blank line)* | **Exit** | Returns to the Woz Monitor (`\` prompt) |

> **Important Note on `$0200`:** Do **not** test cassette saving or loading in the `$0200`–`$027F` page. Just like an original Apple-1, the Woz Monitor and ACI ROM use `$0200` as the live keyboard input buffer, so typing a command overwrites `$0200` before `aci_execute()` runs. Use `$0300` or `$1000` instead.

### Recording to Cassette (`W`)
1. Insert a blank tape, cue past the clear leader, and press **RECORD + PLAY** on the cassette deck.
2. Type your range command with **no filename** (e.g., `0300.03FFW`) and press `RETURN`.
3. The Pico LED turns on and outputs a **10-second 1000 Hz leader tone**, followed by the sync bit, data bytes, and trailing stop cycle.
4. When `OK` appears on screen, press **STOP** on the recorder.

### Loading from Cassette (`R`)
1. Rewind the tape to the start of the recording.
2. Type your range command with **no filename** (e.g., `0300.03FFR`), **without pressing `RETURN` yet**.
3. Press **PLAY** on the cassette deck, wait 1–2 seconds until you hear the steady 1000 Hz leader tone, then press `RETURN`.
4. The Pico calibrates its DC midpoint, locks onto the leader and sync bit, decodes all bytes into RAM, and prints `OK`.

## 3. Apple-1 ACI Audio Protocol Specification

The audio format generated by `aci.c` is 100% compatible with Steve Wozniak's original Apple-1 Cassette Interface hardware and `$C100` ROM:

* **Physical Tape Speed:** Standard compact cassette speed of **1 7/8 ips (4.76 cm/s)**.
* **Leader / Header Tone:** **10 seconds** of continuous **1000 Hz** square wave (10,000 cycles at 500 µs high / 500 µs low) to allow tape deck Automatic Gain Control (AGC) to stabilize.
* **Sync Bit:** One half-cycle of **2000 Hz** (**250 µs** high) followed by one half-cycle of **1000 Hz** (**500 µs** low), marking the exact byte boundary.
* **Data Framing (MSB First):** Bytes are transmitted sequentially from `start` to `end` (inclusive), **Bit 7 down to Bit 0**:
  * **Logic `1`:** One full cycle at **1000 Hz** (500 µs high + 500 µs low = **1000 µs**).
  * **Logic `0`:** One full cycle at **2000 Hz** (250 µs high + 250 µs low = **500 µs**).
* **Trailing Stop Cycle:** One closing cycle at **2000 Hz** (250 µs high + 250 µs low) after bit 0 of the final byte so rising-edge decoders have a clean closing edge for the last bit.

## 4. Firmware Architecture (`aci.c`)

* **`aci_execute(const aci_host_t *h)`**: Reads the command line from the `$0200` monitor buffer and tokenizes memory ranges (`start.endW` / `start.endR`) and optional filenames. When ranges are provided **without** a filename (`nr > 0 && nw == 0`), it routes directly to `tape_audio_write()` or `tape_audio_read()`.
* **`tape_audio_write(const aci_host_t *h, const range_t *rg, unsigned nr)`**: Initializes `GP0` as a digital output and uses `sleep_us()` timing to generate the 10-second 1000 Hz leader, the 250 µs / 500 µs sync bit, the FSK-encoded memory bytes across all requested ranges, and the trailing stop cycle.
* **`tape_calibrate_midpoint(void)`**: Samples `GP26 (ADC0)` across 20 ms (`200` samples at `100 µs` intervals) to determine the exact resting DC bias voltage (`~2048`), compensating for resistor tolerances.
* **`tape_wait_rising_edge(bool *high, uint16_t midpoint, uint64_t deadline_us)`**: Monitors `GP26` with a ±40-count (~32 mV) hysteresis band and measures **rising-edge to rising-edge** full-cycle periods in microseconds. Measuring full cycles cancels out waveform asymmetry caused by tape saturation or op-amp clipping.
* **`tape_audio_read(const aci_host_t *h, const range_t *rg, unsigned nr)`**: Waits up to 30 seconds for at least 60 consecutive 1000 Hz leader cycles (`850 µs – 1300 µs`), locks onto the 750 µs sync cycle (`625 µs – 850 µs`), and decodes each subsequent full cycle (`> 750 µs` = `1`, `<= 750 µs` = `0`) into emulated RAM via `h->write()`.

## 5. Error Codes

| Error Message | Cause & Resolution |
| :--- | :--- |
| `ERR TIMEOUT` | No valid 1000 Hz leader or sync bit detected on `GP26` within 30 seconds. Check that the tape is playing, volume is at 50%–75%, and the 1.65 V bias resistors are connected. |
| `ERR TAPE ERR` | Audio signal dropped out or lost sync mid-transfer. Clean the tape head, check the audio cable ground, or adjust playback volume. |
| `ERR SYNTAX` | Invalid command format or mixed `W` and `R` operations on the same line. |
| `ERR RANGE` | End address is smaller than start address (e.g., `0400.0300W`). |
| `ERR NO SD` | MicroSD card not inserted or failed to mount (only applies when a filename or `*L` / `*R` command is used). |
